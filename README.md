# 产品发布工作台

一个面向 SuperAgent 教程的独立教学副本：六张发布卡片，按待开始、进行中、待确认、已完成四列整理。可以真实拖动卡片；没有后台、额外账号、模型接口或外部数据服务。

界面与拖放代码取自 [Studio Admin](https://github.com/arhamkhnz/next-shadcn-admin-dashboard) 的 Kanban，固定提交 `036631eb6896817649272fe79ded8c80faa709ee`，按 MIT 许可保留版权。原始相关文件位于 `sources/studio-admin/`，具体对应与哈希见 [来源记录](docs/上游来源锁定.json)。这里只提取了本次看板需要的代码，不运行整套管理后台。

## 本地打开

使用 Node.js 24 或更高版本：

```bash
npm ci
npm run dev
```

打开终端返回的本机地址，默认 `http://127.0.0.1:57816/`。

`npm run build` 生成静态文件到 `dist/`；`npm run preview` 可检查构建结果。相对资源路径已设置，可以发布到 GitHub Pages 子目录。

## 这份基线保留的问题

把“演示视频”从“进行中”拖到“待确认”，本页会显示移动成功；刷新后又回到“进行中”。这是为本教程明确保留的教学故障，不声称上游产品存在同样的缺陷。

运行 `npm test`，应看到一项通过、一项失败：失败项检查“重新打开后仍保留新位置”，通过项检查“只移动当前卡片，其他卡片不受影响”。测试调用的内存状态模块，也正是页面拖放时调用的模块。后续由真实 SuperAgent 修复这项问题，不删除或跳过失败测试。

## 留给后续任务的改动

1. 保存并恢复拖动后的状态，刷新后位置不丢。
2. 在同一份修改里增加“生成发布清单”，把未完成事项、负责人和截止时间显示成可复制文字；已完成事项不出现。

这两项在本基线中均未提前实现。演示账户 A 派活、B 接单和 PR 交付由教程实际流程产生，页面没有伪造 Agent 运行记录。
